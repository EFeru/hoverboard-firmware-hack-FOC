Документ подготовлен для наведения порядка в архивах проекта расширения функционала
платы гироскутера. Основа — репозиторий `EFeru/hoverboard-firmware-hack-FOC`
(текущий коммит `4f141cb`, ветка `main`).

> Примечание: ссылки на архивы Yandex.Disk и код Arduino на Yandex.Disk недоступны
> из этого окружения (разрешён только GitHub и несколько пакетных хостов), поэтому

> состоянию основного репозитория и по коду, который есть в репозитории
> (`Arduino/hoverserial/hoverserial.ino`).

## 1. Как устроена одометрия по датчикам Холла

Одометрия включается макросом `ENABLE_ODOMETRY` в `Inc/config.h`:

```c
#define ENABLE_ODOMETRY   // добавляет wheelR_cnt / wheelL_cnt в serial feedback
```

При включении:

### 1.1. Счётчики (Src/bldc.c)

```c
#ifdef ENABLE_ODOMETRY
int16_t odom_l = 0;
int16_t odom_r = 0;
static uint16_t wp_l_prev = 0;   // previous wheel position (left)
static uint16_t wp_r_prev = 0;   // previous wheel position (right)
#endif
```

- `odom_l` / `odom_r` — счётчики тиков, тип `int32_t`, **без оборачивания** (накапливаются со знаком).
- Раньше оборачивались на 9000 тиков = 10 полных оборотов колеса (900 тиков/оборот); теперь счёт идёт непрерывно, переполнение практически недостижимо.

### 1.2. Декодирование состояния датчиков Холла

В прерывании DMA (частота ~16 кГц) считываются три линии Холла:

```c
uint8_t hall_ul = !(LEFT_HALL_U_PORT->IDR & LEFT_HALL_U_PIN);
uint8_t hall_vl = !(LEFT_HALL_V_PORT->IDR & LEFT_HALL_V_PIN);
uint8_t hall_wl = !(LEFT_HALL_W_PORT->IDR & LEFT_HALL_W_PIN);
```

Три бита собираются в один индекс 0..7:

```c
uint8_t encoding = (uint8_t)((hall_ul << 2) + (hall_vl << 1) + hall_wl);
int wheel_pos = rtConstP.vec_hallToPos_Value[encoding];
```

Таблица преобразования (`Src/BLDC_controller_data.c`):

```c
/* vec_hallToPos_Value */
{ 0, 2, 0, 1, 4, 3, 5, 0 }
```

Индексы 0 и 7 (все датчики 0 или все 1 — недопустимые состояния) дают 0,
остальные — номер сектора 0..5 (6 секторов на электрический оборот).

### 1.3. Определение направления

```c
static int16_t hallTickModulo(int16_t m, int16_t n) {
  return (((m % n) + n) % n);
}
static int16_t hallTickDirection(int16_t prev, int16_t curr) {
  static const uint16_t dir_lut[6] = {0, -1, -2, 0, 2, 1};
  return dir_lut[hallTickModulo(prev - curr, 6)];
}
```

- `prev - curr` берётся по модулю 6.
- `dir_lut` переводит разность секторов в приращение: +1 (вперёд на 1 сектор),
  +2 (вперёд на 2), -1/-2 (назад), 0 (без изменения / недопустимый переход).
- Это позволяет корректно считать даже при пропуске одного сектора.

### 1.4. Накопление и знак

Левое колесо:

```c
odom_l = hallTickModulo(odom_l + hallTickDirection(wp_l_prev, wheel_pos), 9000);
wp_l_prev = wheel_pos;
```

Правое колесо (знак инвертирован, т.к. моторы установлены зеркально):

```c
odom_r = hallTickModulo(odom_r - hallTickDirection(wp_r_prev, wheel_pos), 9000);
wp_r_prev = wheel_pos;
```

Счётчик обновляется каждый цикл DMA (~16 кГц), но приращение ненулевое только
в момент смены сектора Холла, поэтому фактическая частота тиков = частота
смены секторов.

### 1.5. Вывод через UART (Src/main.c)

Счётчики экспортируются:

```c
#ifdef ENABLE_ODOMETRY
extern int16_t odom_l;
extern int16_t odom_r;
#endif
```

Структура обратной связи `SerialFeedback` расширяется:

```c
#ifdef ENABLE_ODOMETRY
  int16_t   wheelR_cnt;
  int16_t   wheelL_cnt;
#endif
```

Каждые 10 мс (main_loop_counter % 2 == 0) заполняются и отправляются DMA:

```c
Feedback.wheelR_cnt = (int16_t)odom_r;
Feedback.wheelL_cnt = (int16_t)odom_l;
```

Контрольная сумма XOR включает новые поля:

```c
Feedback.checksum = start ^ cmd1 ^ cmd2 ^ speedR_meas ^ speedL_meas
#ifdef ENABLE_ODOMETRY
                   ^ wheelR_cnt ^ wheelL_cnt
#endif
                   ^ batVoltage ^ boardTemp ^ cmdLed;
```

Размер пакета `sizeof(Feedback)` меняется, поэтому Arduino-скетч на приёмной
стороне должен использовать ту же структуру (см. обновлённый
`Arduino/hoverserial/hoverserial.ino`).

### 1.6. Практические замечания

- Одометрия работает только при вращении колеса: при нулевой скорости сектор
  не меняется, счётчик стоит.
- Оборачивание на 9000 = 10 оборотов. Для накопления большего пробега
  хост (Arduino/ПК) должен сам отслеживать переполнения.
- Направление правого колеса инвертировано в прошивке, поэтому на хосте
  `wheelR_cnt` и `wheelL_cnt` можно складывать напрямую для расчёта пути
  робота (если колёса установлены стандартно).
- Точность: 900 тиков/оборот ≈ 0.4° на тик, достаточно для одометрии
  небольших роботов.

## 2. Что нового в основном репозитории относительно старых наработок

Основной репозиторий `EFeru/hoverboard-firmware-hack-FOC` — это FOC-версия,
отличающаяся от старой коммутационной прошивки (`lucysrausch/hoverboard-firmware-hack`):

1. **FOC-управление** (Field Oriented Control) вместо 6-шаговой коммутации:
   - меньше шум и вибрации, плавный момент, выше КПД;
   - три режима: VOLTAGE / SPEED / TORQUE (`CTRL_MOD_REQ` в `config.h`);
   - ослабление поля (Field Weakening) для увеличения макс. скорости;
   - защита по току и скорости.
2. **Три метода управления**: Commutation / Sinusoidal / FOC (`CTRL_TYP_SEL`).
3. **Варианты сборки** (VARIANT_*): ADC, USART, Nunchuk, PPM, PWM, iBUS,
   HOVERCAR, HOVERBOARD, TRANSPOTTER, SKATEBOARD — выбор в `platformio.ini`
   или `config.h`.
4. **Надёжный последовательный протокол** (start frame 0xABCD + XOR-контрольная
   сумма + повторная синхронизация) — `SerialCommand` / `SerialFeedback`.
5. **Обратная связь** (FEEDBACK_SERIAL): cmd1, cmd2, speedR/L_meas, batVoltage,
   boardTemp, cmdLed, а теперь и wheelR/L_cnt при `ENABLE_ODOMETRY`.
6. **Одометрия по Холлу** (новое, PR #599) — см. раздел 1.
7. **Задержка включения питания** `STARTUP_DELAY_MS` (500 мс) для защиты от
   ложного включения (PR #598, latch-delay).
8. **Приоритеты прерываний** (PR #596): все кроме ADC1 и Fault — 1,0, чтобы
   АЦП не прерывался.
9. **Отключение зуммера** `BUZZER_ENABLED` (PR #573).
10. **Исправленный консольный ввод** (fixed console input, PR #584/#573).
11. **Field Weakening / Phase Advance** с калибровкой.
12. **Fixed-point** параметры контроллера (`BLDC_controller_data.c`), калибровка
    через Fixed-Point Viewer.
13. **Webview** контроллера (без Matlab).
14. **Поддержка GD32F103** в дополнение к STM32F103.
15. **Версия v4** (обновление community links и др.).

Относительно старых «хаков» (коммутационная прошивка) главные изменения:
- переход на FOC/Sinusoidal;
- структурированный `config.h` с вариантами;
- надёжный UART-протокол с контрольной суммой;
- расширенная телеметрия;
- одометрия;
- защита по току/температуре/напряжению.

## 3. Желаемая конфигурация: левый разъём = UART, правый = PWM

Готового варианта «UART слева + PWM справа» в репозитории нет, но его можно
собрать вручную в `Inc/config.h`. База — `VARIANT_USART` (левый кабель:
serial control + feedback) плюс PWM-вход справа.

### 3.1. Вариант (config.h)

Раскомментируйте один из вариантов-основ (например `VARIANT_USART`) и добавьте
PWM-вход справа. Либо не используйте `#define VARIANT_*`, а задайте вручную:

```c
// Левый кабель: UART управление + телеметрия
#define CONTROL_SERIAL_USART2  0
#define FEEDBACK_SERIAL_USART2

// Правый кабель: PWM-вход (RC)
#define CONTROL_PWM_RIGHT      0

// Одометрия
#define ENABLE_ODOMETRY

// Зуммер (по желанию)
#define BUZZER_ENABLED
```

Важные замечания по валидации (`config.h` проверяет совместимость):

- `CONTROL_PWM_RIGHT` и `CONTROL_SERIAL_USART3` / `FEEDBACK_SERIAL_USART3` /
  `DEBUG_SERIAL_USART3` несовместимы (правый кабель один) — не включайте serial
  на правом кабеле при PWM.
- `FEEDBACK_SERIAL_USART2` и `DEBUG_SERIAL_USART2` несовместимы — при UART
  телеметрии слева отладочный serial слева недоступен.
- В `VARIANT_PWM` при PWM справа по умолчанию включается `DEBUG_SERIAL_USART2`
  (для захвата PWM-таймера). При нашей конфигурации (UART слева) этого не
  нужно и даже вредно — не определяйте `DEBUG_SERIAL_USART2`.
- PWM-захват использует прерывания EXTI на правом кабеле и TIM2, независимо
  от serial, поэтому работает.

### 3.2. platformio.ini

В `platformio.ini` выберите окружение (например `default` или `VARIANT_USART`)
и при необходимости добавьте флаги. Поскольку ручная конфигурация не совпадает
с готовым вариантом, удобнее править `config.h` напрямую и собирать
`default`-окружение.

### 3.3. Arduino (приём телеметрии)

Обновлённый `Arduino/hoverserial/hoverserial.ino` уже содержит поля
`wheelR_cnt` / `wheelL_cnt` и правильную контрольную сумму. Если
`ENABLE_ODOMETRY` отключён на плате, верните старую структуру (без wheel-полей)
или условно компилируйте через `#define ENABLE_ODOMETRY` на стороне Arduino.

## 4. Краткая шпаргалка по одометрии для хоста

- `wheelR_cnt`, `wheelL_cnt`: `int32_t`, накапливаются со знаком, 900 тиков/оборот, без оборачивания.
- Направление: при движении вперёд оба счётчика растут (правый инвертирован
  в прошивке).
- Переполнение: хост отслеживает переход 8999→0 и ведёт 32-битный счётчик.

## 6. Сравнение со старыми наработками пользователя (архивы Google Drive)

Архивы пользователя (папка Google Drive) содержат несколько сборок прошивки
с ручными правками. Ключевые наблюдения:

### 6.1. Старая одометрия (zip2/zip3/zip7)

Пользователь уже реализовал одометрию вручную (до появления официальной
`ENABLE_ODOMETRY`), помечая правки комментарием `//YOU` / `// >mod`:

- функции `modulo()` и `up_or_down()` — полные аналоги `hallTickModulo()` и
  `hallTickDirection()` (та же таблица `{0,-1,-2,0,2,1}` и модуль 6);
- счётчики `odom_l`/`odom_r` с оборачиванием на 9000;
- поля `wheelR_cnt`/`wheelL_cnt` в `SerialFeedback` и включение их в XOR;
- `//YOU`-маркеры в `bldc.c` и `main.c`.

Отличия новой официальной версии:
- одометрия вынесена под флаг `ENABLE_ODOMETRY` (в старой — всегда включена);
- функции переименованы и сделаны `static`;
- чистая интеграция в структуру feedback и checksum без ручных правок.

### 6.2. Сборки

| Архив | Вариант | Ток | Режим | Одометрия | Примечание |
|---|---|---|---|---|---|
| zip2 `hboard-luart2-rdebug-...` | VARIANT_USART (левый UART) | 15 A | SPD_MODE | ручная | левый UART управление+телеметрия, правый debug serial |
| zip3 `hboard-lpwm2-rdebug3-...` | VARIANT_PWM (правый PWM) | 5 A | SPD_MODE | ручная | правый PWM, левый debug serial |
| zip7 `eferu_foc_hboard-luart-rpwm-...` | VARIANT_USART + VARIANT_PWM | 15 A | SPD_MODE | ручная | **комбинированная**: левый UART + правый PWM, debug serial слева отключён |
| zip1 `eferu_hoverboard-...-Rpwm-Luart` | VARIANT_PWM | — | SPD_MODE | нет | старая сборка без одометрии |

### 6.3. Что применено в этом репозитории

`Inc/config.h` приведён к комбинированной конфигурации пользователя (zip7):
- включены **оба** варианта `VARIANT_USART` и `VARIANT_PWM`;
- `CONTROL_SERIAL_USART2 = 1`, `FEEDBACK_SERIAL_USART2` (левый UART);
- `CONTROL_PWM_RIGHT = 0` (правый PWM);
- авто-`DEBUG_SERIAL_USART2` в блоке PWM закомментирован (конфликт с feedback);
- `CTRL_MOD_REQ = SPD_MODE`, `I_MOT_MAX = 15 A`, `BAT_CELLS = 10`;
- `ENABLE_ODOMETRY` включена (официальная реализация).

`Arduino/hoverserial/hoverserial.ino` приведён к новой структуре feedback
(с `wheelR_cnt`/`wheelL_cnt`), как в `hoverserial_odom.ino` пользователя.

### 6.4. Что нового в основном репозитории относительно архивов пользователя

## 7. Сравнение архивов пользователя с оригинальным EFeru (разные ли это версии?)

**Да, это разные версии.** Архивы пользователя — это модифицированная (форкнутая) версия
более старой прошивки EFeru с ручными расширениями. Оригинальный EFeru сейчас
содержит одометрию официально, но **не** содержит расширенной телеметрии тока.

### 7.1. Что есть в архивах пользователя, но нет в оригинале

В `SerialFeedback` (zip2/zip3) добавлены поля (помечены `//YOU`):
- `wheelR_cnt`, `wheelL_cnt` — одометрия (в оригинале теперь есть официально);
- `left_dc_curr`, `right_dc_curr` — ток DC-шины левого/правого мотора (в оригинале нет);
- оба поля включены в XOR-контрольную сумму.

То есть «расширенная одометрия + скорость колёс (speedR/L_meas) + ток колеса» —
это именно пользовательские расширения поверх старой прошивки. Скорость колёс
(`speedR_meas`/`speedL_meas`) в оригинале уже была.

### 7.2. Базовая версия архивов

Архивы основаны на более старой версии EFeru (до v4, до официальной одометрии,
до startup delay и приоритетов прерываний). В комментариях zip2/zip3 есть ссылка
на коммит hoverboard-robotics `24955d63` — оттуда взята идея одометрии.

### 7.3. Как вернуть расширенную телеметрию в текущую прошивку

Добавлен флаг `ENABLE_DC_CURRENT_FEEDBACK` в `Inc/config.h` (по умолчанию выключен).
При включении в `SerialFeedback` добавляются `left_dc_curr`/`right_dc_curr` и
включаются в checksum (см. `Src/main.c`). В Arduino-скетче поля добавляются
условно (закомментировано) — раскомментируйте при включении флага.

### 7.4. Итог

- Архивы пользователя = старая прошивка + ручные расширения (одометрия + ток).
- Оригинал EFeru = новая прошивка + официальная одометрия, но без тока в feedback.
- В этом репозитории (ветка) объединено: официальная одометрия + опциональный
  ток (флаг) + комбинированная конфигурация Luart+Rpwm.
