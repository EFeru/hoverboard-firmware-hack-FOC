# Как собрать прошивку и получить `firmware.hex`

Памятка для сборки этой прошивки (FOC, STM32F103) и прошивки платы гироскутера.

**Коротко:** собираем окружение (environment) `VARIANT_LUART_RPWM`
(левый разъём = UART управление+телеметрия, правый = PWM).
Результат сборки: `.pio/build/VARIANT_LUART_RPWM/firmware.hex`.

---

## 1. Что вообще собирается

| Файл | Что это | Зачем нужен |
|---|---|---|
| `firmware.hex` | прошивка в текстовом Intel HEX | этим файлом прошиваем плату (STM32CubeProgrammer / ST-LINK Utility) |
| `firmware.bin` | то же в «сыром» виде | для некоторых загрузчиков/скриптов |
| `firmware.elf` | прошивка + отладочные символы | для отладки (ST-Link + gdb), для прошивки не нужен |
| `firmware.map` | карта памяти | если интересно, сколько занимает код |

Окружение (`env`) определяет набор `-D`-флагов, то есть какие варианты управления
включены. У нас комбинированная конфигурация: `VARIANT_USART` **и** `VARIANT_PWM`
одновременно, поэтому используется специальное окружение `VARIANT_LUART_RPWM`
(остальные окружения в `platformio.ini` — стандартные, «одиночные»).

---

## 2. Вариант A — VS Code + PlatformIO (основной путь)

### 2.1. Подготовка

1. Скачайте/обновите репозиторий на компьютер (просто папка с `platformio.ini`
   внутри):
   ```bash
   git clone https://github.com/marshalab/hoverboard-firmware-hack-FOC.git
   # или, если папка уже есть:
   git checkout main && git pull
   ```
2. Откройте **именно корень репозитория** в VS Code:
   `File → Open Folder…` → папка, где лежит `platformio.ini`.
   Если открыть подпапку — PlatformIO не увидит проект.
3. Расширение: `Extensions` (Ctrl+Shift+X) → в поиске `PlatformIO IDE` → `Install`
   (если ещё не установлено) → перезапустить VS Code.
   В 2025–2026 гг. у расширения есть community-форк **`pioarduino`** — интерфейс
   у него такой же, работать можно и с ним.
4. Дождитесь окончания автоустановки: PlatformIO при первом открытии проекта
   скачивает платформу `ststm32` и ARM-компилятор (~200–300 МБ). Нужен интернет.
   Внизу/в боковой панели будет видно прогресс.

### 2.2. Как собрать

Три равноценных способа, любой на выбор:

**Способ 1 — панель PlatformIO (графически).**
В левой панели VS Code (Activity Bar) нажмите иконку PlatformIO (инопланетянин):

```
PlatformIO → Project Tasks → VARIANT_LUART_RPWM → General → Build
```

В старых версиях кнопки Build/Upload/Monitor показывались в **нижней строке
состояния VS Code** и появлялись только после клика по иконке PlatformIO.
В новых версиях вместо них — боковая панель `Project Tasks` (плюс кнопки
`Build`/`Upload`/`Clean`/`Monitor` в разделе Quick Access).
Наведите мышь на иконки — появятся подсказки.

**Способ 2 — горячие клавиши (работают в любой версии).**

| Клавиши | Действие |
|---|---|
| `Ctrl+Alt+B` | Build (сборка) |
| `Ctrl+Alt+U` | Upload (прошить) |
| `Ctrl+Alt+S` | Serial Monitor (монитор порта) |
| `Ctrl+Alt+T` | меню задач Project Tasks |

`Ctrl+Alt+B` собирает окружения из `default_envs` в `platformio.ini`. В этом
репозитории там уже стоит `default_envs = VARIANT_LUART_RPWM`, поэтому сборка
получится быстрой и нужной. (Если хочется собрать другой вариант — выберите его
через `Project Tasks` явно, либо поменяйте `default_envs`.)

**Способ 3 — командная строка (см. раздел 3).**

### 2.3. Где лежит результат

```
.pio/build/VARIANT_LUART_RPWM/firmware.hex
.pio/build/VARIANT_LUART_RPWM/firmware.bin
.pio/build/VARIANT_LUART_RPWM/firmware.elf
```

Папка `.pio` — **скрытая** (начинается с точки):

* Windows: в проводнике `Вид → Показать → Скрытые элементы`.
* Либо откройте терминал в VS Code (`Ctrl+`` `) и выполните:
  ```bash
  # Windows
  dir .pio\build\VARIANT_LUART_RPWM
  # Linux / macOS
  ls -la .pio/build/VARIANT_LUART_RPWM
  ```
* Либо прямо из VS Code: `Ctrl+P` → набрать `firmware.hex`.

Скопируйте `firmware.hex` в удобное место (например, на рабочий стол) — им
будем прошивать плату.

## 3. Вариант B — командная строка (PlatformIO Core CLI)

Удобно и быстро, особенно для повторных сборок.

1. В VS Code: `PlatformIO → Quick Access → PlatformIO Core CLI` — откроется
   терминал, в котором команда `pio` уже доступна.
2. Или из обычного терминала полным путём (Windows):
   `%USERPROFILE%\.platformio\penv\Scripts\pio.exe`

Команды:

```bash
# собрать нужное окружение
pio run -e VARIANT_LUART_RPWM

# собрать заново с нуля (если что-то странно)
pio run -e VARIANT_LUART_RPWM -t clean
pio run -e VARIANT_LUART_RPWM

# подробный вывод (видно все флаги компилятора)
pio run -e VARIANT_LUART_RPWM -v

# прошить в плату через ST-Link (см. раздел 6)
pio run -e VARIANT_LUART_RPWM -t upload

# монитор порта
pio device monitor -b 115200
```

## 4. Вариант C — GitHub Actions (сборка на сервере, без установки тулчейна)

Если локальная установка не идёт, прошивку может собрать GitHub.

1. В своём форке: `Settings → Actions → General → Actions permissions` →
   выбрать **Allow all actions and reusable workflows** → `Save`.
   (По умолчанию на форках Actions выключены — именно поэтому сборок нет.)
2. Запустить сборку. Workflow срабатывает на **любой push и любой Pull Request**,
   поэтому достаточно сделать любой коммит, например отредактировать файл прямо
   на GitHub (`Actions` → workflow **Build** → `Run workflow` появляется только
   если в workflow добавлен триггер `workflow_dispatch` — см. врезку ниже).
   * Вариант «кнопкой»: откройте `Actions` → **Build** → справа `Run workflow`.
     Если кнопки нет, добавьте в `.github/workflows/build_on_commit.yml` строку
     `workflow_dispatch:  # ручной запуск` в секцию `on:` (удобно сделать прямо
     в веб-редакторе GitHub: значок карандаша → Edit → Commit).
   * Вариант «push-ом»: сделайте любой коммит в `main` (например, поправьте
     перевод строки в любом файле через веб-редактор) — сборка запустится сама.
3. Через несколько минут в завершённом запуске (раздел `Artifacts` внизу
   страницы) появится архив `..._build_N.zip` — скачать и распаковать.
   Внутри: `.pio/build/VARIANT_LUART_RPWM/firmware.hex`.
   Артефакты хранятся **5 дней**.

Сборка также запускается автоматически при каждом `push`/Pull Request.

## 6. Прошивка платы (flash)

### 6.1. ST-Link (рекомендуется)

1. ST-Link V2 (клоны стоят копейки) подключается к площадкам SWD на плате
   гироскутера: **GND, SWCLK (CLK), SWDIO (DIO)** и, если плата не питается
   от батареи, **3.3V**.
2. Программа: **STM32CubeProgrammer** (официальная, бесплатная) или старая
   ST-LINK Utility.
3. `ST-LINK → Connect` → `Open file` → выбрать `firmware.hex` → `Download`.
   Адрес `0x08000000` подставляется автоматически.
4. Или совсем без сторонних программ:
   `pio run -e VARIANT_LUART_RPWM -t upload`
   (в `platformio.ini` уже прописано `upload_protocol = stlink`).

Питание: либо батарея гироскутера, либо 3.3 В от ST-Link (для одной лишь
прошивки этого достаточно, моторы при этом не запустятся).

### 6.2. Альтернатива — заводской UART-загрузчик STM32

Если ST-Link нет: замкнуть BOOT0 на 3.3 В, подать питание, подключить USB-UART
к USART1 (PA9/PA10) и прошить через STM32CubeProgrammer в режиме UART.
На гироскутерах это менее удобно (нужно добираться до пинов), поэтому SWD проще.

## 7. ⚠️ Электрическая безопасность (важно!)

Ваша конфигурация: **левый разъём = UART**.

* В обоих разъёмах есть провод с напряжением батареи (~15–42 В, «красный»).
  **Никогда** не подключайте его к Arduino/ESP32.
* **Левый разъём — это USART2, и он НЕ 5-вольтовый!** Подача 5 В на его вход
  может убить STM32. Если ваш контроллер 5-вольтовый (Arduino Nano/Uno):
  * либо поставьте делитель/преобразователь уровней на линию
    `<Arduino TX> → <STM32 RX>` (например, 1 кОм + 2 кОм),
  * либо используйте **правый** разъём (USART3 — 5 В-толерантный) для UART,
    а PWM — на левом,
  * либо возьмите 3.3-вольтовый контроллер (ESP32, STM32, Raspberry Pi Pico).
* Линия STM32 TX → Arduino RX безопасна: 3.3 В достаточно для входа 5-вольтовой
  логики.

## 8. Нормальные сообщения при сборке (не пугайтесь)

При сборке окружения `VARIANT_LUART_RPWM` компилятор печатает три
предупреждения:

```
warning: "FLASH_WRITE_KEY" redefined
warning: "PRI_INPUT1" redefined
warning: "PRI_INPUT2" redefined
```

Это ожидаемо для **комбинированной** конфигурации: секция `VARIANT_USART` в
`Inc/config.h` определяет эти значения, а затем секция `VARIANT_PWM` определяет
их заново. Побеждают значения из секции PWM (она ниже по тексту файла):

| Параметр | Итоговое значение | Что означает |
|---|---|---|
| `FLASH_WRITE_KEY` | `0x1005` | ключ, по которому читаются калибровки входов из flash |
| `PRI_INPUT1/2` | `3, -1000, 0, 1000, 100` | мёртвая зона 100 (~10 %) вокруг нуля для обоих входов |
| `CTRL_MOD_REQ` | `2` (SPD_MODE) | режим «скорость» |
| `I_MOT_MAX` | `15 A` | ограничение фазного тока |
| `BAT_CELLS` | `10` | батарея 10S |

Проверить, что собралась именно нужная конфигурация (в выводе сборки должны
встречаться оба флага `-D VARIANT_USART` и `-D VARIANT_PWM`):

```bash
pio run -e VARIANT_LUART_RPWM -v          # полный список команд компиляции
# Linux / macOS:  ... -v | grep -E "VARIANT_USART|VARIANT_PWM"
# Windows cmd:    ... -v | findstr "VARIANT_USART VARIANT_PWM"
```

Если мёртвая зона 100 для UART-канала мешает (команды меньше 10 % «не слышны»),
поправьте `PRI_INPUT1`/`PRI_INPUT2` в секции `VARIANT_PWM` на `..., 0` и
пересоберите — но помните, что тогда мёртвой зоны не будет и у PWM-канала.

## 9. Проверка после прошивки

1. Плата включается, слышно два коротких пика — моторы разрешены
   (защита: моторы включаются, только когда входы близки к нулю).
2. Телеметрия (115200 бод, левый разъём): приходят пакеты, в мониторе порта
   видно `1: … 2: … 3: … 4: … 5R: … 5L: … curL: … curR: …`.
3. Одометрия: поднимите колесо, проверните его **ровно 10 оборотов** рукой —
   счётчики `5R`/`5L` должны измениться на **±900**.
4. Токи `curL`/`curR` — в единицах 0.01 А (например, `1234` = 12.34 А).
5. Если в мониторе бесконечно печатается `Non-valid data skipped` — структура
   пакета на хосте не совпадает с прошивкой: пересоберите Arduino-скетч из
   `Arduino/hoverserial/hoverserial.ino` (в нём есть проверка размера пакета).

## 10. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Первая сборка идёт очень долго | скачиваются платформа и ARM-тулчейн (~200–300 МБ), нужен интернет |
| `pio` «не является внутренней командой» | используйте путь `%USERPROFILE%\.platformio\penv\Scripts\pio.exe` или терминал из `PlatformIO → Quick Access → PlatformIO Core CLI` |
| Нет кнопок Build/Upload | кликните иконку PlatformIO в левой панели — панель задач активируется; либо используйте `Ctrl+Alt+B` |
| `firmware.hex` не появился | сборка упала (смотрите вывод) либо собралось другое окружение — проверьте путь `.pio/build/<env>/` |
| Не вижу папку `.pio` | она скрытая (см. 2.3) |
| Ошибка `_Static_assert … SerialFeedback must be 32 bytes` | структура пакета телеметрии изменена — правьте прошивку и скетч Arduino вместе (это защита, а не поломка) |
| Windows: компилятор не найден / странные ошибки путей | перенесите проект в короткий путь без пробелов и кириллицы, например `C:\hw\hoverboard` |
| Прошивка есть, но моторы молчат | проверьте, что собранное окружение то же, входы в нуле (иначе моторы не разрешатся) и что вы не забыли про `TIMEOUT` (команды нужно слать постоянно) |

---

## 11. Что не надо коммитить

Папки `build/` и `.pio/` уже в `.gitignore` — прошивки и промежуточные файлы в
репозиторий не попадают. Не добавляйте `firmware.hex`/`firmware.bin` в git
вручную.

---

## 12. Шпаргалка «я хочу просто hex»

1. Открыть корень репозитория в VS Code (PlatformIO установлен).
2. Дождаться установки платформы при первом открытии.
3. `Ctrl+Alt+B` (или `PlatformIO → Project Tasks → VARIANT_LUART_RPWM → Build`).
4. Открыть `.pio/build/VARIANT_LUART_RPWM/` → скопировать **`firmware.hex`**.
5. Прошить ST-Link'ом через STM32CubeProgrammer (адрес `0x08000000`).
